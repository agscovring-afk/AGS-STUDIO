# AGS-STUDIO V2
# COMMAND REGISTRY POLICY

Version: 2.0
Status: OFFICIAL
Authority: Command Governance
Phase: Knowledge Consolidation

---

# 1. Purpose

This document defines the official governance rules for the AGS-STUDIO V2 Command Registry.

The Command Registry provides the permanent reference for all official commands.

---

# 2. Command Registry Principle

Every official command must be registered.

An undocumented command is considered unofficial.

---

# 3. Command Objectives

The Command Registry ensures:

- Command discoverability.
- Command consistency.
- Command traceability.
- Command maintenance.

---

# 4. Command Information

Each registered command should contain:

- Command name.
- Purpose.
- Category.
- Execution method.
- Status.
- Related documentation.

---

# 5. Command Categories

Commands are organized according to their function:

- Development commands.
- Validation commands.
- Documentation commands.
- Automation commands.
- System commands.

---

# 6. Command Lifecycle

The official lifecycle is:

Creation
→ Validation
→ Registration
→ Usage
→ Maintenance

---

# 7. Direct Commands Policy

Direct execution commands must:

- Be tested before official use.
- Be documented.
- Preserve project integrity.
- Follow project standards.

---

# 8. Command Updates

When a command changes:

- Update the registry.
- Update related documentation.
- Preserve traceability.

---

# 9. Command Relationship With Knowledge Management

Commands are considered project knowledge assets.

They must be stored and maintained as official knowledge.

---

# 10. Command Storage

The official registry is maintained in:

docs/

and synchronized with:

AGS-VAULT/

---

# 11. Single Source of Truth

The Command Registry is the only official reference for project commands.

Duplicate command lists are not permitted.

---

# 12. Compliance

All AGS-STUDIO V2 official commands must comply with this policy.
