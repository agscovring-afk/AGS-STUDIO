---

# 1. Purpose

This document defines the official principles governing AGS-STUDIO V2 development, architecture, documentation, and evolution.

These principles are extracted from approved project decisions.

They represent mandatory rules for maintaining project consistency.

---

# 2. Single Source of Truth

Every official knowledge item must have one authoritative location.

Rules:

- No duplicated official documents.
- Updates must modify the official reference.
- Copies must remain synchronized.
- Conflicting information must be resolved through the official source.

---

# 3. Documentation First

Documentation is a fundamental part of the system.

Rules:

- Decisions are documented before becoming official.
- Architecture is documented before implementation.
- Documentation is maintained throughout the project lifecycle.

---

# 4. Architecture First

Architecture governs implementation.

Rules:

- Implementation must follow approved architecture.
- New components must respect existing structure.
- Architectural changes require documented decisions.

---

# 5. Knowledge Preservation

Validated knowledge must be preserved.

Rules:

- Existing decisions are not lost.
- Previous work is consolidated.
- Knowledge is organized instead of duplicated.

---

# 6. Production Ready Standard

All official project components must target production quality.

Requirements:

- Maintainable structure.
- Clear responsibility.
- Validation before adoption.
- Proper documentation.

---

# 7. Controlled Evolution

AGS-STUDIO V2 evolves through controlled updates.

Rules:

- No uncontrolled changes.
- No random restructuring.
- Changes must maintain project integrity.

---

# 8. Modularity

The system is organized as independent but connected components.

Rules:

- Clear module responsibility.
- Limited coupling.
- Reusable components.
- Maintainable structure.

---

# 9. Consistency

Consistency has priority across:

- Code.
- Documentation.
- Architecture.
- Metadata.
- Registries.
- Commands.

---

# 10. Validation Before Adoption

A component becomes official only after validation.

Validation applies to:

- Architecture.
- Features.
- Commands.
- Documentation.
- Generated components.

---

# 11. Traceability

Every important decision must remain traceable.

Traceability includes:

- Decision source.
- Related documents.
- Version history.
- Impact.

---

# 12. No Duplication Policy

Duplicate solutions and duplicate documentation are avoided.

When new information appears:

1. Locate existing official document.
2. Update it if applicable.
3. Create a new document only when the domain is genuinely new.

---

# 13. Registry Principle

Official project elements must be registered.

Examples:

- Commands.
- Modules.
- Capabilities.
- Documents.
- Architectural decisions.

---

# 14. Automation Principle

Automation must preserve project standards.

Automated processes must respect:

- Architecture.
- Documentation.
- Validation.
- Registry rules.

---

# 15. Knowledge Consolidation Principle

Knowledge Consolidation is the official method for organizing project history.

Objectives:

- Extract decisions.
- Remove repetition.
- Merge knowledge.
- Produce official references.

---

# 16. Future Updates

Future validated information must be integrated into existing official documents whenever possible.

Creating duplicate documentation is prohibited.

---

# 17. Compliance

All AGS-STUDIO V2 components must comply with these principles.

Any conflicting element must be reviewed and corrected.
